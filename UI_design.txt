九、设计质量验收标准
最终 UI 设计稿必须达到以下要求：
整体视觉统一，具有高级海事模拟游戏的质感。
玩家可以直观理解游戏核心玩法。
航海驾驶界面具有明确的视觉优先级。
地图页面具有真实海图的专业感。
港口和贸易页面具有清晰的经济系统视觉。
船舶升级页面具有直观的数值对比。
所有弹窗和异常提示均有明确的交互反馈。
所有页面均适合手机屏幕。
页面布局可以直接拆解成 React 组件。
不出现无法实现的复杂 UI 特效。
所有数据展示具有一致性。
所有主要功能页面均有完整设计，不允许只展示概念稿。
组件可复用，页面结构可扩展。
整体风格应具有商业级手游 UI 的完成度。
最终目标：
创建一套完整的《远洋纪元：真实海域》移动端游戏 UI 设计体系，使其能够直接作为后续 React 18 + TypeScript + Tailwind CSS + Zustand 项目开发的视觉设计依据。
请先建立全局 Design System，再按照页面清单逐页设计，最后完成 UI Flow Diagram、Modal Library 和 Component Library。
不要只输出设计建议。请实际生成完整的高保真设计稿。
我建议你特别注意的地方
这份提示词的页面数量比较多，不建议让图像生成模型一次生成全部页面。一次性生成容易出现：
不同页面风格不统一  
小字乱码  
页面内容被压缩  
功能遗漏  
弹窗与主页面设计风格不一致  
更合理的执行方式是：
先生成全局 Design System 和主界面。  
以主界面为视觉基准，生成航海、海图、港口等核心页面。  
再生成船舶成长、任务、天气等功能页面。  
最后统一生成 Modal、Toast、Bottom Sheet 组件库。  
优先级最高的 5 个页面是：主菜单、航海驾驶、全球海图、港口主页、船舶管理。
这些页面决定整个游戏的视觉语言，其余页面应继承它们的设计风格。
